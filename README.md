# CS340
Students will learn how to apply database systems concepts and principles to develop client/server applications that interface client-side code with databases.


How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?
- I try to write programs that are maintainable, readable, and adaptable by keeping my code organized, using clear names for variables and methods, adding comments, and handling errors so the program doesn't just crash when something goes wrong. The CRUD Python module from Project One is a good example. I built it as a class with separate create, read, update, and delete methods, and each method had a clear input and return value. Because the database logic was kept in its own module, I didn't have to rewrite any of it in Project Two. I just imported the module into the dashboard and used the read method to pull data for the table, the filters, and the charts. That made the dashboard code shorter and easier to follow, and if something went wrong with the database connection I knew exactly where to look. It also follows the MVC pattern, since the CRUD module works as the controller between the MongoDB model and the dashboard views. In the future, I could reuse this module in any Python project that needs to work with a MongoDB database, like another dashboard, a data entry ap, or a script that updates records automatically. With small changes to the connection settings, it could work with a completely different database and collection.

How do you approach a problem as a computer scientist? Consider how you approached the database or dashboard requirements that Grazioso Salvare requested. How did your approach to this project differ from previous assignments in other courses? What techniques or strategies would you use in the future to create databases to meet other client requests?
- When I approach a problem as a computer scientist, I start by making sure I understand what the client actually needs before I write any code. For Grazioso Salvare, that meant reviewing the dashboard specifications and the rescue type and preferred breeds table so I knew what each filter had to return such as the breed, sex, and age range for water rescue dogs. From there I broke the project into smaller pieces. I set up the database and authentication first, then built and tested the CRUD module, then built the dashboard one part at a time, starting with the data table and then adding the filters and charts. I tested each piece before moving on, which made problems much easier to find. This was different from many of my previous assignments, which usually gave me a specific problem with a clear answer. This project felt more like real client work, because I had to turn business requirements into database queries and design something  a non-technical user could work with. In the future, I would keep using this approach for other client requests, such as gathering the requirements first, planning the data structure and queries around what the client needs, building in small testable steps, and writing documentation so others can maintain the work.

What do computer scientists do, and why does it matter? How would your work on this type of project help a company, like Grazioso Salvare, to do their work better?
- Computer scientists solve problems by using technology to make information easier to store, access, and understand. It matters because most organizations have a lot of data but don't always have an easy way to use it. Grazioso Salvare had access to thousands of animal shelter records, but searching through them by hand to find dogs that fit their training profiles would take a lot of time. The dashboard I built lets their staff filter the data by rescue type with one click and instantly see a table of matching dogs, a map of where they are, and a chart breaking down the results. That saves them time, reduces mistakes, and doesn't require them to know anything about databases or code. Because the project is open source on GitHub, other rescue organizations could also use and adapt it for their own needs. Work like this helps a company focus on its actual mission, which for Grazioso Salvare is finding and training dogs that save lives.
